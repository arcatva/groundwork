# Ship

Get the PR in front of reviewers with nothing they must ask for.

**Safety.** Push, open a PR, post or merge only on the user's go-ahead for that action; one
go-ahead is not the next. Work on a branch, never the default one.

## 1 · Before the push

The review has run or the user declined it, and the repo's checks pass or the user accepted each
failure.

## 2 · The PR description

The repo's PR template where it has one; otherwise the PR description shape of `contracts.md`:
every change the diff makes and nothing it does not, the commands run and what they showed, and
each product decision with its source.

Check it as the Claims reviewer in `review.md` does.

## 3 · After review comments

Fix each comment, or answer it with the evidence that the code is right. Resolve or answer a thread
only on the user's go-ahead.

**Gate.** The description matches the diff, and the user gave the go-ahead for each outward action.
